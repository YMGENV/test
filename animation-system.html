Performance-Optimized Animations

Smooth, GPU-accelerated page transitions and interactions that work on older devices.

Animation System Overview

This demonstration shows production-ready animation patterns optimized for:

  • GPU Acceleration: Only opacity and transform properties animate
  • Mobile Performance: Reduced motion on touch devices, respects prefers-reduced-motion
  • Consistent Timing: CSS variables control all animation durations (150ms, 250ms, 400ms)
  • Staggered Effects: Cards fade in with cascading delays for visual interest

Key Animation Patterns

1. Page Transitions

@keyframes pageEnter { from { opacity: 0; transform: translateY(8px); } to { opacity: 1; transform: translateY(0); } } main { animation: pageEnter 250ms cubic-bezier(0.2, 0.8, 0.4, 1) forwards; will-change: opacity, transform; }

Pages fade in from below with a subtle lift. Use will-change: opacity, transform to hint to the browser for optimization.

2. Card Fade-In with Stagger

.video-card { animation: cardFadeIn 250ms ease-out backwards; } .video-card:nth-child(n) { animation-delay: calc(n * 80ms); }

Each card cascades in with an 80ms stagger, creating a polished sequence. backwards ensures the initial state is applied before animation starts.

3. Hover Lift with Micro-Interactions

.video-card { transition: transform 150ms cubic-bezier(0.4, 0, 0.2, 1); } .video-card:hover { transform: translateY(-2px); }

Subtle 2px lift on hover signals interactivity. Only transform animates for 60fps performance.

4. Button States (Hover + Active)

.btn:hover { transform: translateY(-1px); } .btn:active { transform: scale(0.98); }

Hover provides visual feedback; active state offers tactile confirmation. Scale is cheaper than width/height changes.

Mobile & Accessibility

@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; } } @media (max-width: 768px) and (hover: none) { .video-card:hover { transform: none; /* No hover lift on touch */ } }

Always respect user preferences: If a user has enabled "reduce motion" in their OS, all animations compress to 1ms. On mobile touch devices, hover effects are disabled to avoid unexpected motion.

React + Tailwind Implementation

To port this to React + Tailwind, use framer-motion or headlessui with Tailwind's animation utilities:

{/* Option 1: Tailwind CSS animations */} <div className="animate-fade-in">Content</div> {/* Option 2: Framer Motion for advanced control */} <motion.div initial={{ opacity: 0, y: 8 }} animate={{ opacity: 1, y: 0 }} transition={{ duration: 0.25, ease: 'easeOut' }} > Content </motion.div> {/* In tailwind.config.js: */} animation: { fadeIn: 'fadeIn 250ms cubic-bezier(0.2, 0.8, 0.4, 1) forwards', } keyframes: { fadeIn: { '0%': { opacity: 0, transform: 'translateY(8px)' }, '100%': { opacity: 1, transform: 'translateY(0)' }, }, }
